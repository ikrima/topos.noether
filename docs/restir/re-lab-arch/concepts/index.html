Explanation

learner · practitioner · contributorauthoredcurrent

Explanation answers why re-lab has this shape and how its parts fit together. Start with a compact mental model, then descend into implementation territory without changing vocabulary or losing the source trail.

Orient in the system

Follow the architecture atlas from lowering layers through sampling domains, state, and the proof-carrying pixel.

Understand estimator evolution

Start with two reservoirs, two promises to see why the direct-light and path-contribution families share sampling mechanics but not one semantic contract.

Trace one frame

Use system boundaries and retained-state design to follow data from authored assets to inspection and capture.

Reason about render networks

Move from the conceptual overview to the approved architecture and execution design.

Reading paths

Section titled “Reading paths”
  • New to the project: two reservoirs → architecture atlas → proof-carrying pixel.
  • Estimator researcher: two reservoirs → bias/support/Jacobians → interactive atlas.
  • Backend engineer: system boundaries → backend portability → backend lowering.
  • Graph or tooling contributor: render-network overview → approved architecture → execution design → state/replay/capture.
  • Planning a code change: technical-design index → change the architecture safely.

Authored explanations synthesize architecture, implementation, and proof sources for learning. Their evidence notes lead to exact repository contracts when needed. Generated status and reference pages continue to project executable or planning authority; current milestone truth lives in ROADMAP.md, TODO.md, and the active execution packet.
