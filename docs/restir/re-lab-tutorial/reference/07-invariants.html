Invariants

Every cross-cutting contract, where it is enforced, and which test guards it.

Source: docs/architecture/reference/07-invariants.mdinformation-oriented

Every cross-cutting contract, where it is enforced, and which test fails if it breaks. If you are changing the estimator, this is the checklist.

The governing invariant#

Every estimator lives twice, and the twins agree per sample.

Enforced bytests/test_kernels.py::TestRestirGiKernels::test_agrees_with_the_reference_per_pixel and its DI siblings
ToleranceREL_TOL = 5e-3, MAX_DISAGREE_FRACTION = 0.02, plus p99 < 1e-3 and means within 2e-3
Breaks whenyou change core/ or kernels/ without the other

The DI/GI tests are parametrized over mis, naive and pairwise-mis — including naive precisely because it is the wrong estimator. The kernel and the reference must agree about what the wrong answer is, or a downstream bias measurement would be measuring a kernel bug.

Three assertions of decreasing locality, the same shape in all three twin tests:

rel = np.abs(ker - ref) / np.maximum(np.abs(ref), 1e-3)
assert float((rel.max(axis=2) > REL_TOL).mean()) < MAX_DISAGREE_FRACTION
assert np.percentile(rel, 99) < 1e-3
assert ker.mean() == pytest.approx(ref.mean(), rel=2e-3)

Trap — reciprocity does not pin a Jacobian's direction. J(a→b)·J(b→a) == 1 holds just as well if the whole ratio is inverted, and the identity case has the same blind spot. What closes it is arithmetic done by hand on an asymmetric configuration: a vertex twice as close must give J = 4, not 1/4. Both numbers are asserted, on both implementations, rather than one being derived from the other.

Empty streams#

Two separate halves, and missing either is expensive.

HalfRuleCost of missing it
Inside the mergecombine_streams absorbs (None, w=0, m_add=s.res.M)reference W off from the kernel's by a clean factor of two
Choosing streamsthe code deciding which neighbours become streams must not filter on having a samplethe canonical stream counted twice; 25% bright at K=3

Guarded by TestEmptyStreamConfidence, including test_an_empty_spatial_neighbour_still_dilutes_the_canonical. Kernel side: usable() tests M > 0.0, not .valid.

Measured, indirect energy at K=1/3/5: dropping empties 1.086 / 1.201 / 1.284; counting their confidence 1.002 / 1.006 / 1.005. Total image energy read a healthy 0.9953 throughout.

And the rule inverts for the temporal pass. Spatial streams are admitted on M > 0; temporal streams on y is not None. A spatial neighbour is fresh this-frame candidates, so its confidence belongs in the denominator regardless; an empty history carries an M already spent. Treating them the same took the indirect term from 0.993 to 0.939.

Measurement#

These are not code invariants but protocol ones. Violating them produces confident wrong answers, which is worse than a crash.

RuleWhy
Discard 64 warm-up frames before measuring a reuse estimator's energya ReSTIR run becomes the estimator over ~m_cap frames; from cold the deficit is invisible
Warm the no-reuse control identically; it must read 1.000otherwise the discard itself is suspect
Measure ReSTIR variance per frame, never accumulatedconsecutive frames are correlated through the reservoirs
Energy may be accumulated (it is a mean) — after the warm-up discard
On the indirect term, trust energy over MSEbias² on 11–18% of an image never clears both variances
Aggregate over the frame; per-pixel probes are uselessheavy-tailed enough to show fake bias on a DI control
Score a differenced image against the indirect noise floor1.4e-06 vs 5.8e-03 — the whole-image floor calls everything clean
FLIP ranks and localizes; it does not detect biasa converged biased estimator scores well

When a measurement settles something, add it to ARCHITECTURE.md's Findings worth keeping and reference it from the code that depends on it. Recording the hypotheses that were eliminated is worth as much as the answer — that file does this deliberately, and finding 23 alone records three eliminations plus one non-finding.

Each finding is a ### heading with a stable anchor. A new one also needs an entry in docs/site/findings.json giving it a tag set and a status; the documentation build asserts the two stay in bijection, so nothing can be added or renamed without being classified.
