The build_* thunk protocol#

Every kernel module exports factories with one shape:

def build_<pass>(cctx: CompileContext) -> Callable[[RenderContext], None]

The factory captures the fields its pass declared, defines a @ti.kernel, and returns an execute(ctx) closure the plan calls each frame.

Contract — nothing shell-mutable may be a compile-time capture. Camera, sample index, seed, bias mode, spatial radius and the reproject flag are kernel arguments, never captured. Anything captured requires a full Engine.rebuild() to change; anything passed is free. This is exactly why set_seed costs nothing and with_resolution costs ~5s.

def build_restir_temporal(cctx):
    sd    = cctx.scene_device
    hits  = cctx.field_by_name("hits")          # captured: declared resources
    M     = int(cctx.params.get("M", 8))        # captured: compile-time params
    @ti.kernel
    def run(sample: ti.i32, seed: ti.i32, temporal_on: ti.i32, bias_mode: ti.i32,
            reproject_on: ti.i32, p_eye: ti.math.vec3, ...):   # arguments: per frame
        ...

Device structs — runtime.py#

Reservoir = ti.types.struct(
    y_p=ti.math.vec3, y_light=ti.i32, valid=ti.i32,
    w_sum=ti.f32, M=ti.f32, W=ti.f32)      # M is float so capping can be fractional

PathReservoir = ti.types.struct(
    y_p=ti.math.vec3,   # x2, the reconnection vertex
    y_n=ti.math.vec3,   # normal at x2, for the geometry term after a shift
    y_L=ti.math.vec3,   # L(x2 -> x1), emission at x2 excluded
    y_pdf=ti.f32,       # solid-angle pdf as drawn at x1
    y_prim=ti.i32, valid=ti.i32, w_sum=ti.f32, M=ti.f32, W=ti.f32)

Contract — these mirror core/types.py field for field, so the two implementations can be diffed per field rather than only per pixel.

Two structs rather than one payload union, deliberately: Taichi structs are fixed-layout, so a union would cost the DI path the space, and the "the Jacobian is 1 because we store a world-space point" comments scattered through the DI code would become only conditionally true. The reuse algebra is not duplicated — only the payload. See core/reservoir.ReuseDomain.

Taichi constraints worth knowing#

Four threading rules and two syntax rules that fail unhelpfully. All are enforced or worked around in runtime.py and engine.py.

ConstraintWhat a violation looks like
ti.init() binds the LLVM context to the calling thread; only that thread may allocate fields. Launching kernels and to_numpy() elsewhere is fine.Assertion failure: std::this_thread::get_id() == main_thread_id_ from llvm_context.cpp — no mention of threads owning fields
Field materialization is deferred until first access, so allocating on the right thread is not enough — it must be touched there.The same assertion, but at first render rather than construction, so building appears to have succeeded
The default root FieldsBuilder is finalized on first materialization; no field can be created afterwards.TaichiRuntimeError: FieldsBuilder finalized when a second engine is built
Writing to a field forces materialization, illegal while a caller-owned FieldsBuilder is open.Field builder … is not finalized, raised from inside an innocuous data upload
Any kernel launch validates that no builder is open — including one launched by another thread.A rebuild on the main thread kills the render worker mid-frame with a bare TaichiRuntimeError

Two more, unrelated to threading and both liable to bite while editing:

  • from __future__ import annotations breaks Taichi. PEP 563 stringifies annotations, and Taichi reads @ti.kernel / @ti.func argument annotations as live type objects. No module under pt/kernels/ may use it. Every one carries a note.
  • ti.template() does not thread a scalar through a @ti.func. It passes fields by reference, not local scalars, so a stateful RNG whose counter is "advanced" by a callee silently returns the same number every draw — and the output still looks like plausible noise. This is why the RNG is stateless and indexed.

How the inlined algebra corresponds#

The kernels are combine_streams with N fully expanded. In build_restir_temporal, the two-stream merge evaluates p̂ for both samples at both shading points (ph_t_q, ph_c_q, ph_t_t, ph_c_t), which is mis_weights_at's density(i) loop unrolled:

if bias_mode == _NAIVE:
    w_prev = ph_t_q * pr.W * m_prev                 # unnormalized 1/M form
else:
    den_t = m_c * ph_t_q + m_prev * ph_t_t
    w_prev = (m_prev * ph_t_t / den_t) * ph_t_q * pr.W
    den_c = m_c * ph_c_q + m_prev * ph_c_t
    out.w_sum = out.w_sum * ph_c_q / den_c          # canonical re-weighted too
    mis_merged = 1

Contract — finalize is selected by an explicit flag, not inferred. mis_merged exists because "no history was found" and "history was found and weighted" are different states that can leave M looking the same:

if mis_merged == 1: out.W = out.w_sum / ph          # finalize_mis
else:               out.W = out.w_sum / (out.M * ph)  # finalize_ris

Contract — pairwise-mis is not a third branch in the temporal kernel. With exactly two streams it reduces to the balance heuristic term for term, so it shares the mis path. Measured bit-identical.

The GI spatial kernel is the fullest mirror, factoring the MIS denominator into a @ti.func whose body is mis_weights_at's density summed:

@ti.func
def mis_denominator(idx, sample, seed, y_p, y_n, y_L, y_hit, canon_M, rad) -> ti.f32:
    """`sum_j M_j * p_hat_j(y) * J(y's domain -> j)`."""

Contract — the two Jacobian directions are different calls. Inside the denominator, J(y_hit → stream i); at the absorb site, J(stream i → q). The DI kernels contain no Jacobian factor at all — the × 1 is elided, which is the concrete meaning of DI_DOMAIN.jacobian = unit_jacobian.

Contract — usable() tests M > 0, not valid. This is the kernel spelling of combine_streams's empty-stream rule; has_sample() is a separate predicate consulted only at the absorb site. See 07-invariants.
