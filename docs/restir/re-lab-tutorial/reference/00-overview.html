The mass distribution is deliberate: the reference implementation is nearly as large as the fast one, because they are diffed against each other.

The two load-bearing ideas#

1. Functional core, imperative shell — with the boundary at the pass.

pt/core/ is genuinely pure. pt/kernels/ mutates freely, because pretending otherwise would make it slow and awkward for no benefit. The contract sits at the pass boundary instead: a pass may only touch resources it declared, and its declared outputs are a deterministic function of its declared inputs, params and seed. pt/graph/compile.py enforces this by handing each pass a scoped CompileContext — reaching for an undeclared buffer raises when the graph is built, not on some later frame.

2. Counter-based RNG.

Every stochastic decision is hash(pixel, sample, bounce, dim, seed). ti.random() is banned. Three consequences the design leans on:

  • the pure reference and the Taichi kernel draw the same numbers, so they can be diffed per sample rather than statistically;
  • clicking a pixel re-derives the path that was actually traced, so the inspector shows evidence rather than a plausible re-roll;
  • the worker can be interrupted and restarted and still produce identical images.

See 02-core for the dimension layout, which is a documented contract between pt/core/rng.py and pt/kernels/_common.py.

The estimator matrix#

Two orthogonal axes — what transport and how it is sampled:

:uniform:ris:restir-di:restir-gi
:direct-lighting (1 bounce)di_uniformdi_risdi_restirrejected
:global-illumination (≥2)gi_uniformrejectedrejectedgi_restir (exactly 2)

Rejections are elaboration errors with codes — GI_STRATEGY_UNSUPPORTED, GI_BOUNCE_EXACTLY_TWO, DI_BOUNCE_CONSTRAINT. See 01-dsl.

integrator_for treats bounce count as the second axis: UNIFORM with max_bounces > 1 selects gi_uniform, not a fifth strategy.

Changing one without the other breaks tests/test_kernels.py::TestRestirGiKernels::test_agrees_with_the_reference_per_pixel and its DI siblings — which is the point of them.

The algebra itself is not duplicated. core/reservoir.py holds one copy for both payloads, parameterized by a ReuseDomain. See semantics.md.
