pt/graph/ — the render graph

Resources, passes, the five compile stages, the execution plan.

Source: docs/architecture/reference/03-graph.mdinformation-oriented

Frostbite-style: declare → compile → execute, as three separate objects.

assemble_di_graph(scene)  ->  RawGraph        declare: no memory exists yet
compile_graph(raw, ...)   ->  ExecutionPlan   order · cull · lifetimes · alias · guard
plan.run(ctx, only=...)                       execute: walk a schedule, no reasoning
ModuleLinesRole
resource.py74ResKind, ResourceDesc, ResourceHandle (SSA)
pass_.py55PassDecl and DIRTY_DOMAINS — the whole pass model
builder.py263GraphBuilder, RawGraph, assemble_di_graph
compile.py290CompileContext, compile_graph, the five stages
plan.py155ExecutionPlan, PlanStep, Lifetime, dirty propagation

The whole layer is ~860 lines and has no Taichi import on the reasoning path — field allocation is injected, which is why tests/test_graph.py exercises ordering, culling, lifetimes, aliasing and the boundary contract with a FakeField stub and no GPU.

Resources — resource.py#

class ResKind(Enum):
    RAY_BUF, HIT_BUF, RADIANCE, MOMENT, RESERVOIR, PATH_RESERVOIR, AOV, FRAMEBUFFER

@dataclass(frozen=True)
class ResourceDesc:
    kind: ResKind; shape: tuple; dtype: str = "f32"; transient: bool = True
    @property
    def key(self):    # aliasing bucket — only exact matches may share memory
        return (self.kind, tuple(self.shape), self.dtype, self.transient)

@dataclass(frozen=True)
class ResourceHandle:
    id: int; name: str; desc: ResourceDesc; version: int = 0
    def written(self) -> ResourceHandle:   # a write yields a NEW SSA version
        return replace(self, version=self.version + 1)

Contract — the transient/persistent split is load-bearing. Persistent resources (reservoir_prev, reservoir_temporal, reservoir_curr, hits_prev, radiance_accum, moment2) survive across frames and are never aliased. The distinction recurs consistently in four places, and all four must agree:

WhereBehaviour for persistent resources
_resolve_producersmay be read at version == 0 with no producer
_lifetimesLifetime(-1, n) — live forever
_assign_slotsnever share a slot
default_keep_alivenever culled

That first row is what makes ReSTIR temporal reuse legal at all: reading last frame's reservoir is an unproduced read, and the exemption is stated precisely enough that nothing else slips through it. zero_persistent() is the only way to clear them.

Note on aliasing. The key bucket requires an exact descriptor match, which is deliberately conservative — a smarter allocator would alias compatible-but-unequal descriptors. On the real scenes no aliasing actually fires: every transient is either an AOV or the framebuffer, both kept alive, and hits and primary_rays sit in different buckets. The mechanism is exercised only by tests/test_graph.py::TestAliasing::test_aliasing_happens_when_lifetimes_are_disjoint, which builds a synthetic 4-pass graph.

Passes — pass_.py#

The entire pass model is 55 lines:

DIRTY_DOMAINS = frozenset({"scene", "camera", "spp", "exposure", "aov"})

@dataclass(frozen=True)
class PassDecl:
    name: str
    reads: tuple = ()
    writes: tuple = ()
    params: dict = field(default_factory=dict)
    build: Callable = None            # (CompileContext) -> ExecuteFn
    invalidated_by: frozenset = frozenset()
    cost_hint: float = 0.0
    def __post_init__(self):          # a typo'd dirty domain is a compile error
        unknown = set(self.invalidated_by) - DIRTY_DOMAINS
        if unknown: raise ValueError(...)

Contract — the referential-transparency boundary. A pass may only touch resources it declared; its declared outputs are a deterministic function of its declared inputs, params and seed. The contract lives here, not inside the kernels, which mutate fields freely.

Declaring — builder.py#

class GraphBuilder:
    def create(self, name, desc) -> ResourceHandle          # id = len(self._resources)
    def import_persistent(self, name, desc) -> ResourceHandle  # rejects transient descs
    def add_pass(self, decl) -> PassDecl
    def build(self) -> RawGraph

class RawGraph:
    resources; passes; scene
    def resource_by_id(rid); def resource_by_name(name)

assemble_di_graph(scene, kernels=None) -> RawGraph

assemble_di_graph is the single place the Uniform → RIS → ReSTIR-DI → ReSTIR-GI progression is expressed. It validates depth/strategy pairings at declare time, creates resources, then branches only on the shade node. DI and GI share the ReSTIR branch verbatim, differing in three values:

gi     = strat == int(Strategy.RESTIR_GI)
prefix = "ReSTIR.GI." if gi else "ReSTIR."
resv_desc = ResourceDesc(ResKind.PATH_RESERVOIR if gi else ResKind.RESERVOIR,
                         (N,), "struct", transient=False)

ReSTIR GI is not a fourth graph. tests/test_graph.py::TestRestirGiGraph asserts pass-by-pass that it is the DI graph with a different payload.

The declared ReSTIR schedule:

Passreadswritesinvalidated_by
{prefix}InitialAndTemporalhits, reservoir_prev, hits_prevreservoir_temporalcamera, scene
{prefix}Spatialhits, reservoir_temporalreservoir_currcamera, scene
{prefix}CopyToCurrentreservoir_temporalreservoir_curr(when spatial is off)
{prefix}Resolvehits, reservoir_currradiance_accum, moment2, aov_reservoircamera, scene, spp

Contract — spatial reuse reads one buffer and writes another. Read-modify-write on reservoir_curr is a race the moment the pass runs in parallel: each pixel would see an arbitrary mixture of updated and stale neighbours. One extra buffer removes the hazard rather than documenting it.

Note — the reuse passes omit spp. This is a true fact about the declaration and it is what progressive_steps() was designed around. It does not mean those passes are skipped when the sample index advances: dirtiness also flows along data edges, and hits is rewritten every sample by Intersect, so in practice dirty_steps({"spp"}) marks every step of a ReSTIR graph. A declaration is a lower bound on what re-runs, not the last word.

Compiling — compile.py#

compile_graph(raw, scene_device=None, make_field=None, keep_alive=None) -> ExecutionPlan

Five stages, in Frostbite's order:

StageFunctionJob
A_resolve_producers(res_id, version) → producing pass. Double write = error; unproduced read = error except version == 0 and not desc.transient
B_toposortKahn's algorithm, ties broken by declaration index
C_cullbackward reachability from default_keep_alive = {"framebuffer"} ∪ AOVs ∪ persistents
D_lifetimes → _assign_slots → _allocate_fields[first_write, last_read], greedy interval colouring per desc.key, one physical field per slot
Ebuild loopa CompileContext per pass → decl.build(cctx) → PlanStep

Contract — determinism of stage B. Ties broken by declaration index, not by hash order, because stable buffer assignment and RNG stream layout depend on it.

Contract — the injection seam. make_field and kernels are both injected. This is what makes the graph testable without a GPU and is the seam a port would reuse.

CompileContext#

What a build_* closure sees — scoped to exactly one pass, so field capture and declaration checking happen at the same moment:

class CompileContext:
    def __init__(self, scene, scene_device, fields_by_name, allowed, params, pass_name)
    def field_by_name(self, name):
        if name not in self._allowed:
            raise GraphError(
                f"pass {self._pass_name!r} touched undeclared resource {name!r} — "
                f"it declared {sorted(self._allowed)}. Add it to reads/writes, "
                f"or the graph cannot reason about lifetimes and dirtiness.")
        return self._fields[name]
    def has(self, name) -> bool

allowed is {h.name for h in (decl.reads + decl.writes)}. Guarded by tests/test_graph.py::TestBoundaryContract.

The plan — plan.py#

@dataclass(frozen=True)
class Lifetime:  first: int; last: int;  def overlaps(other) -> bool

@dataclass(frozen=True)
class PlanStep:  name; index; pass_index; exec_fn; invalidated_by; reads; writes; params

@dataclass(frozen=True)
class ExecutionPlan:
    steps; fields_by_id; fields_by_name; physical; resources; lifetimes; slot_of; culled; scene
field_by_name(name)      has_field(name)      resource_by_name(name)    step_by_name(name)
data_edges()             # (producer_step, consumer_step) pairs, derived from resource ids
dirty_steps(changed)     # seeded from invalidated_by ∩ changed, then transitive closure
progressive_steps()      # == dirty_steps({"spp"})
run(ctx, only=None)
zero_persistent()
describe()

Three distinct meanings of "run less work", easily confused:

MechanismWhenScope
stage-C cullingcompile timepermanent — the pass is not in the plan
dirty_steps(changed)per interactionwhich steps a UI change forces
progressive_steps()steady statewhat a new sample needs

dirty_steps is what the shell calls on an exposure or AOV change:

only = engine.plan.dirty_steps({"exposure", "aov"})
engine.plan.run(engine.ctx, only=only)
