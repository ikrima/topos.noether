pt/core/ — the pure reference

Types, the RNG dimension layout, geometry, the reuse algebra, the integrators.

Source: docs/architecture/reference/02-core.mdinformation-oriented

Genuinely pure: no I/O, no globals, no mutation of inputs, f64 throughout. This is the denotational spec. The Taichi kernels are f32 and must agree with it per sample, so a disagreement points at structure, not float noise.

Value types — types.py#

Ray(origin, dir, pixel=-1, sample=0)
Hit(valid=False, t=inf, p, n, wo, material_id=-1, prim_id=-1, light_id=-1, pixel=-1)

All frozen dataclasses. LightSample and PathSample are the two reservoir payloads, and the difference that matters is which measure their density is in: pdf_area for a light point, pdf_solid_angle for a path suffix. That single fact is why DI needs no Jacobian and GI does.

RNG — rng.py#

Every stochastic decision is a pure hash. There is no stream state anywhere.

pcg(v: int) -> int
hash4(pixel, sample, bounce, dim, seed=0) -> int    # argument order is part of the contract
uniform_from(h: int) -> float                       # (h >> 8) * 2^-24
rand1(pixel, sample, bounce, dim, seed=0) -> float
rand2(pixel, sample, bounce, dim, seed=0) -> (float, float)

Mixing constants (_PCG_MUL, _PCG_INC, _PCG_XSH, _K_PIXEL, _K_SAMPLE, _K_BOUNCE, _K_SEED, _INV_2_24) are duplicated verbatim in kernels/_common.py. tests/test_kernels.py::TestRngParity pins the pair bit for bit.

The bounce axis — one stream per path vertex#

BOUNCE_CAMERA        = 0   # primary-ray generation
BOUNCE_SHADE         = 1   # direct lighting / initial RIS candidates, at the primary hit
BOUNCE_TEMPORAL      = 2   # ReSTIR temporal reuse
BOUNCE_SPATIAL       = 3   # ReSTIR spatial reuse
BOUNCE_BSDF          = 4   # path extension, all vertices
BOUNCE_SHADE_INDIRECT = 5  # NEE at path vertex 1; vertex k uses 5 + (k - 1)

shade_bounce(depth) -> BOUNCE_SHADE if depth == 0 else BOUNCE_SHADE_INDIRECT + depth - 1

Contract — vertex 0 keeps BOUNCE_SHADE at any depth. A two-bounce render draws exactly the numbers a one-bounce render draws at its first vertex. This is what makes L(2 bounces) − L(1 bounce) the indirect term per sample, exactly, rather than statistically — the basis of the entire GI validation path (06-validation).

Deeper vertices get their own bounce id rather than an offset inside BOUNCE_SHADE, because the candidate block there is M · CAND_STRIDE wide with M a runtime parameter — any fixed offset would collide for some M, invisibly.

The dim axis#

BounceStrideSlotsAccessor
0 camera—DIM_JITTER = 0 (+1 for the second axis)—
1 shadeCAND_STRIDE = 4CAND_PICK=0 CAND_U=1 CAND_V=2 CAND_ACCEPT=3cand_dim(i, which)
2 temporal—DIM_TEMPORAL_ACCEPT = 0—
3 spatialTAP_STRIDE = 4TAP_ANGLE=0 TAP_RADIUS=1 TAP_ACCEPT=2tap_dim(k, which)
4 bsdfBSDF_STRIDE = 2BSDF_U=0 BSDF_V=1bsdf_dim(depth, which)
4 bsdf (GI ReSTIR)GI_CAND_STRIDE = 3GI_CAND_U=0 GI_CAND_V=1 GI_CAND_ACCEPT=2gi_cand_dim(i, which)

Contract — the GI alias. GI candidates share bounce 4 with path extension, aligned so candidate 0's (u, v) are dimensions 0 and 1 — exactly bsdf_dim(0, ·). That is what lets ReSTIR GI at M=1 with reuse off be compared to the two-bounce uniform path tracer per sample — they draw the same numbers. The outputs are not bit-identical: the bounce ray leaves from x1 + eps * n, so reuse re-derives a direction differing from the sampled one by about eps / d. See core/integrators/gi_restir.py. The price: candidate i > 0 overlaps vertex i's BSDF dimensions, so a path reservoir cannot coexist with a >2-bounce path. Enforced in elaborate.py as GI_BOUNCE_EXACTLY_TWO.

Trap. Adding a draw means allocating a dimension in both core/rng.py and kernels/_common.py, or two "independent" draws silently become the same number — which looks exactly like plausible noise. See 08-extending.

Geometry and the two epsilons — geometry.py#

intersect_plane / intersect_sphere / intersect_quad / intersect_prim
intersect_scene(scene, ray) -> Hit               # closest hit, linear scan
intersect_scene_any(scene, o, d, max_dist) -> bool   # any-hit in [EPS, max_dist)
prim_normal_at(prim, p)
shadow_epsilon(dist) -> float                    # SHADOW_EPS + dist * SHADOW_REL
scatter_epsilon(dist) -> float                   # SCATTER_EPS + dist * SCATTER_REL
EPS         = 1e-4    # minimum accepted intersection distance
SHADOW_EPS  = 1e-3    SHADOW_REL  = 1e-4
SCATTER_EPS = 1e-4    SCATTER_REL = 1e-5

Contract — the two epsilons must not share a scale, and neither may cancel.

Two findings live here, both in ARCHITECTURE.md:

  • "A shadow-ray epsilon that cancels itself" — offsetting the origin forward by eps and shortening the far end by eps makes the two cancel, putting the light's own surface exactly on the t < limit boundary, decided by rounding, which f64 and f32 resolve differently. It caused 31% of pixels to disagree reference-vs-kernel; shortening by twice the offset took that to 0.2%.
  • "A bounce ray's epsilon and a shadow ray's solve different problems" — a shadow ray's margin scales by its own length; a bounce ray has no far endpoint yet, so reusing the shadow formula scales it by the primary ray's length (~1300 units in the Cornell box), putting the origin 0.13 units off the surface. Worst-sample identity error: 169%. SCATTER_REL = 1e-5 was measured, not argued.

Contract — light_sample_at is exact. Re-deriving wi and dist from a stored world-space point loses nothing, which is precisely why DI_DOMAIN pairs phat_at with a Jacobian that is identically 1.

Target modes#

Modep̂
UNSHADOWEDLe · cos_light / d² — no BRDF, no receiver cosine
UNSHADOWED_COSINEfull f · Le · G, unshadowed (the default)
FULLincludes visibility — one ray per candidate; reserved

p̂ is unshadowed by default because tracing a shadow ray per candidate would defeat the point of resampling. Resample against the cheap target, then trace exactly one shadow ray for the survivor.

The reuse algebra — reservoir.py#

The module the project's subtlest bugs have all lived in. Full treatment in semantics.md; this is the API.

@dataclass(frozen=True)
class Reservoir:
    y: LightSample = None   # the surviving sample; None when empty
    w_sum: float = 0.0      # running sum of resampling weights
    M: float = 0.0          # confidence — float, so capping can be fractional
    W: float = 0.0          # contribution weight the shading pass multiplies by
    @property valid -> bool  # y is not None and W > 0

@dataclass(frozen=True)
class Stream:
    res: Reservoir; hit: Hit; kind: str = "canonical"; pixel: int = -1

@dataclass(frozen=True)
class ReuseDomain:
    name: str
    phat: Callable        # (scene, hit, y, target_mode) -> float
    jacobian: Callable = unit_jacobian   # (scene, y, from_hit, to_hit) -> |d(to)/d(from)|
empty() -> Reservoir
update(r, cand, w, u) -> Reservoir              # = absorb(r, cand, w, 1.0, u)
absorb(r, y, w, m_add, u) -> Reservoir          # Chao's weighted reservoir sampling
finalize_ris(r, phat_y) -> Reservoir            # W = w_sum / (M · p̂(y))
finalize_mis(r, phat_y) -> Reservoir            # W = w_sum / p̂(y)
phat_at(scene, hit, y, mode) -> float           # the DI target hook
unit_jacobian(scene, y, from_hit, to_hit) -> float   # constantly 1.0
mis_weights_at(scene, streams, y, target_mode, bias_mode, domain=DI_DOMAIN, y_hit=None)
combine_streams(scene, hit_q, streams, accept_draws, target_mode=…, bias_mode=…,
                capture=False, domain=DI_DOMAIN) -> (Reservoir, records)

DI_DOMAIN = ReuseDomain(name="di", phat=phat_at, jacobian=unit_jacobian)

Contract — Stream carries the hit, and must. An MIS weight asks "how likely was each contributing stream to produce this sample?", which cannot be answered without knowing the shading point each stream was defined at.

Contract — a stream that found nothing still has confidence M. combine_streams absorbs (None, w=0, m_add=s.res.M) for an empty stream. Two findings turn on this; see 07-invariants.

Contract — a domain is a value, not a subclass. Deliberate: a test injects a knowingly wrong Jacobian and asserts the answer moves (tests/test_core.py::TestReuseDomain).

The shift mapping — reconnect.py#

@dataclass(frozen=True)
class Reconnection:
    wi; dist; cos_shade; cos_vertex; g; valid

reconnect(scene, y: PathSample, hit) -> Reconnection
reconnection_jacobian(scene, y, from_hit, to_hit) -> float
gi_contribution(scene, hit, y) -> (rgb, Reconnection)
gi_phat_at(scene, hit, y, mode=UNSHADOWED_COSINE) -> float
reconnection_occluded(scene, hit, y, rc=None) -> bool

DIST_EPSILON = 1e-6
GI_DOMAIN = ReuseDomain(name="gi", phat=gi_phat_at, jacobian=reconnection_jacobian)

GI_DOMAIN lives here rather than in reservoir.py to avoid an import cycle.

The Jacobian, with both cosines at x2:

J(r → q) = |dω_q / dω_r| = (cos_q / d_q²) · (d_r² / cos_r)

Three deliberate non-choices, each recorded as a finding:

  • No clamp on J. Clamping silently rewrites the estimator. A grazing reconnection is a large finite number, which is the correct answer and a genuine firefly.
  • No grazing-cosine threshold. reconnect decides two things — whether a shift exists, and whether the target is non-zero — and an epsilon for the first silently did the second, zeroing p̂ for the canonical stream's own sample. A target that is zero where the contribution is not is biased, full stop. Found by the per-sample identity against the uniform path tracer and by nothing else.
  • Measure choice is exclusive. gi_contribution returns f · cos(θ₁) · L in solid angle, not f · G · L in area, because G already contains the conversion the Jacobian applies.

Precondition. Reconnection is legal at all only because every material is Lambertian, so L(x2→x1) is view-independent. This is the first thing that breaks with a glossy BSDF.

di_restir and gi_restir expose the same four signatures, one per render-graph pass, which is what lets validation diff reference-vs-kernel per pass:

initial_and_temporal(scene, hit, pixel, sample, prev=None, *, M, target, temporal,
                     m_cap, bias_mode, capture, prev_hit, prev_pixel)
spatial_reuse(scene, hit, pixel, sample, curr, neighbors, *, target, spatial_count,
              bias_mode, capture)
resolve(scene, hit, res)          # -> (radiance, occluded, sample | None)
shade(...)                        # -> (radiance, Reservoir, PathNode | None)

Only three things differ between them: generate_path_candidates instead of _shared.generate_candidates, domain=GI_DOMAIN at both combine_streams call sites, and resolve going through gi_contribution. gi_restir.shade additionally adds a separate uniform NEE term at x1 — the reservoir carries the indirect term only.

Geometric gates are imported from di_restir by gi_restir, because they ask whether two pixels are on the same surface, which is a question about shading points and not about the payload:

neighbor_offsets(pixel, sample, width, height, count, radius, seed=0) -> list[int]
accept_neighbor(hit_q, hit_n) -> bool          # cos >= 0.9 and |Δt| < 0.1 · max(|t|)
reprojected_pixel(prev_cam, hit) -> int        # -1 means no history, never a fallback
accept_reprojection(hit_q, hit_prev) -> bool   # PLANE distance, not eye distance

NORMAL_THRESHOLD = 0.9   DEPTH_THRESHOLD = 0.1   PLANE_THRESHOLD = 0.02

Contract — the temporal gate is not the spatial gate. accept_neighbor compares hit.t, distance from the eye: fair within one frame, invalid across a moving camera. Dolly 20% and a perfectly reprojected static point fails, discarding all reuse exactly when it would pay. accept_reprojection uses plane distance, |dot(p_prev − p_q, n_q)| < 0.02·t, which tolerates the tangential slop a floored pixel index guarantees while still catching a disocclusion.

Contract — the spatial/temporal admission asymmetry. Spatial streams are admitted on nres.M > 0; temporal streams on prev.y is not None. A spatial neighbour is a fresh reservoir over candidates drawn this frame, so its confidence belongs in the denominator regardless. An empty history carries an M already spent diluting earlier frames, and feeding it back is a feedback loop. Measured: treating them the same took the indirect term from 0.993 to 0.939.

The frame loop — render.py#

trace_hits(scene, sample, pixels=None) -> {pixel: Hit}
render_reference(scene, spp=None, on_progress=None, cameras=None) -> (H,W,3) float64
render_reference_frames(scene, cameras, on_progress=None) -> (F,H,W,3)
estimate_pixels(scene, pixels, spp, strategy=None) -> {pixel: (r,g,b)}

_render_restir carries (res_prev, hits_prev, cam_prev) across frames. Per frame: retrace all primary hits → pass 1 for every pixel → pass 2 for every pixel → pass 3 → rollover.

Contract — the pass split is a correctness requirement. Spatial reuse reads this frame's post-temporal reservoirs, so every pixel must finish pass 1 before any pixel starts pass 2. Otherwise each pixel samples an arbitrary mixture of updated and stale neighbours. The graph enforces the same thing by having spatial reuse read reservoir_temporal and write reservoir_curr.

Contract — the history rollover differs by payload.

res_prev = res_temporal if mod is gi_restir else res_curr
hits_prev = hits

GI rolls the pre-spatial reservoir. Rolling the post-spatial one lets a sample travel between pixels and come back as a second stream offering the same draw to the same merge; the balance heuristic then counts one draw's probability k times. Measured: 31% distinct vertices, indirect term 0.955 at m_cap 20 falling to 0.939 at 60; rolling reservoir_temporal forces duplication to exactly 1.00 and the deficit flattens at ~0.990 with the m_cap scaling gone entirely. DI keeps the post-spatial roll because every DI number in ARCHITECTURE.md was measured under it.

Contract — reservoirs and hits roll together. reservoir_prev[i] was built at hits_prev[i].

Engine._make_advance is the device twin of this and must not drift.

Path trees — pathtree.py, pathtree_types.py#

Re-runs one pixel with capture=True. Because of the RNG contract this reproduces the path that was actually traced — evidence, not a re-roll. pathtree_types.py holds the node builders (candidate_node, chosen_node, reuse_node, reconnection_node, shadow_node, bounce_node, …) that are the schema contract with the debug UI.
