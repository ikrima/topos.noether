Verify the Racket port

Generate a fixture, check the port against it, then mutation-test the checker — the third step is not optional.

Source: docs/how-to/verify-the-racket-port.mdtask-oriented

port/racket/ reimplements the thinking layers — pt/dsl/, pt/graph/, pt/core/ — as #lang restir/estimator. Kernels and the converged-reference oracle stay in Python. All eight steps are done.

Verification has three parts, and the third is not optional.

1. Generate a fixture from Python#

python docs/architecture/conformance/gen_conformance.py            # step 1 — RNG
python docs/architecture/conformance/gen_scene_conformance.py      # step 2
python docs/architecture/conformance/gen_geometry_conformance.py   # step 3
python docs/architecture/conformance/gen_reservoir_conformance.py  # step 4
python docs/architecture/conformance/gen_reconnect_conformance.py  # step 5
python docs/architecture/conformance/gen_graph_conformance.py      # step 6

Each writes a JSON of golden values into docs/architecture/conformance/. What each file pins is tabulated in Conformance vectors.

Fixtures must be language-neutral JSON. Python's json.dump emits a bare Infinity, which is a Python extension that conforming readers reject. Encode non-finite values as strings and pass allow_nan=False.

To check the Python against its own frozen vectors without regenerating anything:

python docs/architecture/conformance/verify_conformance.py

2. Check the Racket against it#

raco test port/racket

Two claims are asserted separately, and the split matters:

  • every compared value is within a 1e-12 relative tolerance, allowed for the three libm calls in the path (tan in the camera basis, sqrt in every length, sin/cos in the sphere light);
  • every compared value is exactly equal.

Measured, the tolerance has never been used: all 55,184 values agree bit for bit. It stays because a different platform libm is a real possibility and the alternative is a suite that fails for a reason it cannot explain. But only the exactness check catches a one-ulp defect — and there has been one. Reverting the compensated sum below is invisible to the tolerance and immediately visible to exactness.

Keeping them separate also makes failure legible: if the exactness check is the only one failing, the port is fine and the platform's libm differs.

3. Mutation-test the checker#

port/racket/test/mutations.sh     # ~3 min

Deliberately break the port and confirm the suite notices. A fixture generated from an implementation tests only the branches that implementation happens to take, and that set is consistently smaller than it looks.

What this has actually caught:

  • A broken harness. The script grepped for "failed" where raco test prints "failures", so eight real mutations read as passes.
  • EPS is unreachable through a render. Every ray a scene traces starts either at the camera or at a shading point already offset by shadow_epsilon, which is 1e-3 at minimum — an order of magnitude above EPS = 1e-4. Deleting the guard changes no pixel of any scene. It still has to be right, because bounce rays are what it exists for.
  • Every quad in every bundled scene is a rectangle. intersect_quad solves against a 2×2 Gram matrix whose off-diagonal is dot(u, v); with rectangles that is exactly zero, so the two terms carrying it vanish identically. Corrupting one is a no-op on all nine scenes.
  • Two acceptance gates that agree trivially on near neighbours. Only distant partners on the same plane separate them.

Both of the first two are now covered by calling the intersection routines directly with hand-chosen rays, rather than by hoping a scene reaches them.

Recording a mutation that is not caught#

Some mutations should not be caught, and the reason is the useful artifact. Add it to the expected-uncaught list in mutations.sh with the reason written out — six are recorded there now. An unexplained entry is indistinguishable from a gap.

Two host differences that will bite any port#

CPython's sum() over floats is Neumaier-compensated since 3.12, not a left fold: sum([0.1]*10) is exactly 1.0 where folding left gives 0.9999999999999999. core/reservoir.py uses it in the balance heuristic's denominator and in NAIVE's Σ M_j. The disagreement appears only with three or more live streams, because compensated and naive summation coincide for two — which means it is invisible in the temporal merge and shows up only under spatial reuse. The port implements Neumaier explicitly rather than inheriting it: port/racket/vecmath.neumaier-sum.

Python's negative list indexing has no equivalent in a conforming host. materials[-1] returns the last material and looks plausible; a port that raises is right, and the fixture is what has to change.

Do not reorder the steps#

Every step's acceptance is a per-sample diff against the Python, which is only possible because step 1 makes both draw the same numbers. Falling back to statistics is not an option: statistics on ~11% of an image will not see a defect losing a sixth of the indirect term.
