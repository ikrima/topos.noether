Dump and diff an intermediate

You changed the front end. Did the IR change the way you meant?

Source: docs/how-to/dump-and-diff-an-intermediate.mdtask-oriented

Every level between the scene text and the kernels is a first-class artifact you can print and diff. Use that instead of guessing what a change did.

Did the elaborated scene change?#

.venv/bin/pt edn cornell > /tmp/before.edn
# … make your change …
.venv/bin/pt edn cornell > /tmp/after.edn
diff /tmp/before.edn /tmp/after.edn

pt edn prints the SemanticIR — the scene after resolve, default, normalize, stitch and expand. It is the level everything downstream consumes, so if this file is unchanged, no front-end change you made can have reached the renderer.

This also round-trips: elaborate(read(to_edn(ir))) == ir is asserted for every bundled scene, so anything pt edn prints is a scene you can feed back in.

Did the schedule change?#

diff <(.venv/bin/pt describe cornell        2>/dev/null) \
     <(.venv/bin/pt describe cornell_restir 2>/dev/null)

pt describe prints the compiled ExecutionPlan: the pass order, each pass's declared reads and writes, its dirty domains, and every resource with its lifetime interval and physical slot.

This output is a stronger acceptance test than it looks. Because it prints slot numbers, requiring it character-for-character transitively pins declaration order, the topological tie-break, culling, the lifetime intervals and the greedy colouring's first-fit rule — five things with no numeric output of their own. The Racket port is held to it verbatim for exactly that reason.

If you changed the graph and describe is byte-identical, you changed nothing the scheduler can see.

Did the buffers change?#

.venv/bin/pt dump cornell --res 64 64 --spp 8 --dir out/before
# … make your change …
.venv/bin/pt dump cornell --res 64 64 --spp 8 --dir out/after
.venv/bin/python - <<'EOF'
import numpy as np, glob, os
for a in sorted(glob.glob("out/before/*.npy")):
    name = os.path.basename(a)
    x, y = np.load(a), np.load("out/after/" + name)
    if x.shape != y.shape:
        print(f"{name}: shape {x.shape} -> {y.shape}")
    elif not np.array_equal(x, y):
        d = np.abs(x.astype(np.float64) - y)
        print(f"{name}: {(d > 0).mean():.2%} of values differ, max {d.max():.4g}")
EOF

Keep the resolution and sample count small and identical between the two runs. Because every draw is a hash of (pixel, sample, bounce, dimension, seed) rather than a stateful generator, two runs of unchanged code produce byte-identical buffers — so any difference at all is your change, not scheduling noise.

That property is also the trap: if your change added a random draw without allocating a new dimension, the buffers will differ for a reason that has nothing to do with what you intended, and it will look like plausible noise. See Add a random draw.

The two levels with no CLI#

forms and SceneAST have no pt subcommand. Dump them with:

.venv/bin/python docs/explainer/capture_levels.py

which writes every stage for cornell.edn into docs/explainer/levels/ in one pass, shelling out to pt describe for the compiled plans so the output is the real CLI's rather than a reimplementation. Re-run it after changing the DSL front end or the graph builder, or the explainer goes stale.
