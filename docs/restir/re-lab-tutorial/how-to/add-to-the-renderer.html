Add a draw, a pass, a strategy, a scene

Recipes that list every file which must change together.

Source: docs/architecture/reference/08-extending.mdtask-oriented
This page renders docs/architecture/reference/08-extending.md, which lives in the reference directory for historical reasons. It is a how-to guide, so it is filed as one.

Recipes. Each lists every file that must change together — the failure mode in this codebase is changing one half of a twin.

Add a random draw#

The most dangerous change in the repo, because getting it wrong looks like noise.

  1. Allocate a dimension in pt/core/rng.py: either a new *_STRIDE/slot pair under an existing bounce, or a new BOUNCE_* id.
  2. Mirror it in pt/kernels/_common.py. The constants are duplicated verbatim on purpose.
  3. Check it collides with nothing: dimensions are stride-indexed and some strides are runtime-scaled (M · CAND_STRIDE). If your offset is fixed and the block is variable-width, it will collide for some M, invisibly.
  4. Run tests/test_kernels.py::TestRngParity and the per-pixel twin tests.

Do not reuse an existing (bounce, dim) "because that draw is unused here". The GI candidate dimensions deliberately alias bsdf_dim(0, ·), and that alias is load bearing and documented; a second, undocumented one is a silent correlation.

Add a target mode#

  1. pt/dsl/ir.py — extend TargetMode; TARGET_NAMES derives automatically.
  2. pt/dsl/analyze.py — add the surface name to _TARGETS.
  3. pt/core/shading.py::target_phat — the DI branch.
  4. pt/core/reconnect.py::gi_phat_at — the GI branch, same three-way shape.
  5. pt/kernels/_common.py — target_phat and gi_target_phat.
  6. Twin tests, then a bias verdict — a new target changes the estimator, so it owes a pt validate run, not just green tests.

FULL already exists as an enum member and is reserved: it includes visibility, so it traces a ray per candidate.

Add a pass#

  1. Declare it in pt/graph/builder.py::assemble_di_graph: a PassDecl with reads, writes, params, build, and invalidated_by ⊆ DIRTY_DOMAINS.
  2. Create or import its resources — create for transient, import_persistent for anything crossing a frame.
  3. Write build_<pass>(cctx) -> execute(ctx) in pt/kernels/. Capture only declared fields and compile-time params; everything shell-mutable is a kernel argument.
  4. If it participates in reuse, add the reference twin in pt/core/integrators/ and wire it into core/render._render_restir.

Checklist:

  • Reading and writing the same buffer is a race. Split it.
  • Omitting spp from invalidated_by does not mean the pass is skipped when the sample advances — dirtiness also flows along data edges.
  • A new persistent resource must be in zero_persistent's reach (it is, via desc.transient) and will never be aliased or culled.
  • tests/test_graph.py runs the whole graph suite with FakeField and no GPU. Add there first; it is seconds rather than minutes.

Add a strategy#

The heaviest change; the existing four are the template.

  1. pt/dsl/ir.py — extend Strategy.
  2. pt/dsl/analyze.py — add to _STRATEGIES.
  3. pt/dsl/elaborate.py — the transport × strategy matrix, with a new ERROR_CATALOG code for each illegal pairing. Do not let an invalid combination reach the graph.
  4. pt/graph/builder.py — a branch in assemble_di_graph. If it is a payload variation of an existing strategy, reuse the branch as ReSTIR GI does rather than writing a second graph.
  5. pt/core/integrators/<name>.py — the reference, exposing shade(...), plus the four pass functions if it participates in reuse.
  6. pt/core/integrators/__init__.py — register in _BY_STRATEGY.
  7. pt/kernels/ — the twin.
  8. pt/scenes/<name>.edn — a scene that exercises it.

If it resamples a new payload, the reservoir algebra should not grow a second copy. Add a ReuseDomain — a phat hook and a jacobian hook — and a device struct. See semantics.md. core/reservoir.py growing a second copy of the combination algebra is the outcome to avoid; the project's subtlest bugs have all lived in that one.

Add a scene key#

  1. pt/dsl/analyze.py — the closed key set, and a parser in _PRIM_FIELDS if it is primitive-specific.
  2. pt/dsl/ast.py — the field.
  3. pt/dsl/elaborate.py — lower it; add an ERROR_CATALOG code if it can be wrong.
  4. pt/dsl/ir.py — the IR field, plus a with_* edit if anything varies it.
  5. pt/dsl/writer.py — emit it, or the round-trip law breaks.
  6. pt/kernels/scene_device.py — upload it, if the kernels need it.

The round-trip test will catch step 5 for you. Nothing catches a missing step 3.

Add a scene#

Drop an .edn in pt/scenes/. It loads by bare name everywhere.

A scene intended to exercise an estimator needs design, not just geometry:

  • "Many lights" is not a light count. Sixteen lamps in a ceiling grid look like the resampling regime but are not: every floor point sees them at similar distance and angle, target values differ by under 2×, and RIS beat uniform by ~2%. Scattering the same sixteen through the volume at varied heights, sizes and intensities is what creates the condition.
  • Reuse bias needs neighbours that pass the gate and still disagree. Geometry discontinuities are the wrong place to look — the similarity gate already rejects those. On an ordinary Cornell box :naive and :mis differ by 0.2%, under the noise floor. bias_demo uses lights perpendicular to a flat floor, so cos_light flips sign along a razor line across a plane and two adjacent pixels are geometrically identical while disagreeing about which samples are possible.
  • Avoid fireflies, or the statistics break. bias_demo v1 used small intense emitters; error went heavy-tailed, one realization landed 15× above its own expectation, and the harness reported uniform MC as biased against a uniform reference with a convergence slope of +0.71. reproject_demo v1 had posts through the back wall, putting wall points at distance ~0 from a samplable light point; MSE ran 25000× the median and the detector read +0.14× excess on an estimator losing a tenth of the scene's light. Moving the posts inside dropped MSE 37× and the same test read +2.57× and fired.

Change the estimator at all#

Read ARCHITECTURE.md's "Findings worth keeping" first — the relevant entries will save you rediscovering a dead end already written down. Then:

  1. Change the reference and the kernel.
  2. Run the per-pixel twin tests. They are the fastest signal.
  3. Run pt validate <scene> for a verdict. Green tests are not a correctness claim; low variance is not correctness.
  4. For a GI change, measure the indirect term with 64 warm-up frames discarded, and read energy before MSE. See 07-invariants.
  5. Add what you measured to "Findings worth keeping", including the hypotheses you eliminated.
