Build the documentation

This site and the explainer, from a clean checkout.

Source: docs/how-to/build-the-docs.mdtask-oriented

There are two built documents: this site, and the interactive explainer. Both are stdlib-only Python and need no venv.

Build the site#

python docs/site/build.py
41 files, 1128 KB
  27 document pages · 4 section indexes · 40 findings · 71 search entries
  explainer: 262 KB

open file:///…/docs/site/dist/index.html

Output lands in docs/site/dist/, which is gitignored. Open index.html directly with file:// — nothing is fetched at runtime, so there is no server to run. The search index ships as a <script> assigning a global, because fetch() is blocked on file://.

--no-explainer skips folding in the interactive page, which is the only step that shells out.

Build only the explainer#

python docs/explainer/build.py
# then open docs/explainer/dist/index.html

It emits two files: index.html (standalone, with a theme toggle) and artifact.html (the bare fragment, for publishing as a hosted Artifact). The fragment carries no <!doctype>/<html>/<head>/<body> because the host supplies them; index.html wraps that identical fragment in the same skeleton, so what you read locally is what gets published.

What the build refuses to do#

It fails, loudly and with a line number, on:

  • a dangling cross-reference — a Markdown link that resolves to neither a page of the site nor a file in the repository;
  • a Markdown construct the renderer does not implement — images, reference-style links, setext headings, raw HTML blocks. Dropping a construct silently would produce a page that looks fine and is missing a paragraph;
  • drift between docs/site/findings.json and ARCHITECTURE.md — the sidecar must name every finding and no others. Rename a finding and the build tells you which entry to update.

Regenerating the inputs#

Two steps need the venv and are run by hand, because their output is committed. This is deliberate: it keeps the build dependency-free.

.venv/bin/python docs/site/capture_cli.py         # pt --help transcripts, scene catalogue
.venv/bin/python docs/explainer/capture_levels.py # every pipeline level for cornell.edn
.venv/bin/python docs/explainer/prep_figures.py   # explainer figures — needs out/*.png

Run capture_cli.py after changing pt/cli.py or anything in pt/scenes/, and capture_levels.py after changing the DSL front end or the graph builder. Neither is checked automatically; a stale capture produces a correct-looking page.

prep_figures.py needs renders that are gitignored:

.venv/bin/pt render bias_demo --bias naive -o out/bias_naive.png --spp 300
.venv/bin/pt render bias_demo --bias mis   -o out/bias_mis.png   --spp 300

Where to edit#

Not in dist/, and not in the HTML. Every page of the site renders a Markdown file that lives in the repository; each page names its source in the header line under the title. Edit that file.

Adding a page means adding it to docs/site/nav.py, which is where the Diátaxis classification lives — the site does not infer which mode a document belongs to, because that judgement is the whole point.
