Porting to Racket

The essential-vs-incidental split, the eight-step order of work, and the traps already hit at real cost.

Source: docs/architecture/porting-to-racket.mdunderstanding-oriented

A specification for reimplementing the thinking layers of this system as #lang restir/estimator, treating the Python as the reference implementation.

Scope. Port pt/dsl/, pt/graph/, and pt/core/ — the front end, the render graph, and the pure-f64 reference that is the denotational spec. The Taichi kernels and the converged-reference oracle stay in Python.

The goal is not a faster renderer. It is a substrate where the estimator is something you write and the compiler can check — where ARCHITECTURE.md's findings stop being commit diffs and become programs you can hold side by side.

Why Racket, in one detail#

The original design brief said "use a Python EDN library." The shipped reader is 283 hand-written lines. The reason is spans: a stock reader gives you none, and spans are what let errors.py's 23-code catalog point a caret at the offending form.

syntax/parse provides exactly that, free — source locations threaded through macro expansion, structured error reporting, and a macro stepper that shows the lowering happening. The port's justification is not performance or elegance; it is that this design had to hand-build the one thing the host would have given it.

Essential vs incidental#

The distinction that governs everything below. Reproducing the incidental column is wasted work; getting the essential column wrong produces a plausible, wrong renderer.

The single most transferable line: if your reimplementation and the Python draw the same numbers, you can diff them per sample. If they do not, you are back to statistics, and statistics on ~11% of an image will not see a defect losing a sixth of the indirect term.

Roughly 900 of pt/dsl/'s 2,020 lines evaporate. elaborate.py does not — its five jobs (resolve, default, normalize, stitch, expand) are domain logic, not parsing.

Do not lose the accumulate-then-raise behaviour. raise-syntax-error reports the first problem; Diagnostics reports all of them. A scene with four mistakes should report four. This needs deliberate work in Racket, and it is worth it.

What becomes writable#

The point of the exercise. In the Python these are hardcoded; all of them are already data in shape.

Step 8 built this, and the sketches below are close to what shipped. port/racket/estimator.rkt is the language and port/racket/estimators.rkt is written in it. Three differences from the sketch are worth recording, because each was forced by the code rather than chosen:

  • A rule needs an id, not just a name. The weighting is selected by an integer that the scene IR and the Taichi kernels both agree on, so a rule has to be addressable across the device boundary. define-mis-rule takes #:id, and registering two rules on one id is an error.
  • define-rng-layout has to separate bounces from blocks. A bounce is a stream id; a block is the repeating group inside it. Bounce 1 is "shading" and the thing repeated inside it is a candidate — conflating them, as the sketch did, cannot express the layout that actually exists.
  • The frame loop's third pass needs an adapter and the first two do not. initial+temporal and spatial have identical shapes across both payloads; resolve differs by what else is in the pixel — GI adds a next-event sample at the primary hit — so it is declared as a procedure rather than named.
(define-reuse-domain gi
  #:target   gi-phat-at
  #:jacobian reconnection-jacobian)   ; |dω_q / dω_r|, both cosines at x2

(define-mis-rule balance
  #:weights (λ (streams y)
              (normalize (for/list ([s streams]) (density s y)))))

(define-pass ReSTIR.GI.Spatial
  #:reads  [hits reservoir_temporal]
  #:writes [reservoir_curr]
  #:dirty  [camera scene])

(define-rng-layout
  [bounce shade    #:stride 4 #:slots (pick u v accept)]
  [bounce bsdf     #:stride 2 #:slots (u v)]
  [bounce gi-cand  #:stride 3 #:slots (u v accept) #:aliases (bsdf 0)])

Two things a language buys that a library does not:

Findings become diffs. Finding 23 — the defect that took the most work — is two lines:

(define-frame-loop restir-gi
  #:passes  (initial+temporal spatial resolve)
- #:history reservoir_curr)        ; a sample can travel and return
+ #:history reservoir_temporal)    ; duplication forced to 1.00

Obligations become checkable. The unbiasedness requirement currently lives in a docstring and a parametrized test. As a judgment it can be stated once and randomly tested against every rule anyone writes — including the quantifier distinction that prose keeps blurring:

(define-judgment-form partition-of-unity
  #:contract (⊢ rule streams y)
  [-------------------------------------------
   (⊢ rule streams y)
   (side-condition (≈ 1.0 (Σ (mᵢ rule streams y))))])

Redex can generate streams and y and look for a counterexample. Note this must be stated over a fixed y — mᵢ(yᵢ), which the estimator actually uses, does not sum to one. A define-rng-layout form can likewise check injectivity statically, which is the class of bug that currently only shows up as plausible noise.

Each step ends with something checkable against the Python.

Step 1 is not optional and not reorderable. Every later verification is a per-sample diff, and a per-sample diff requires identical draws. Its acceptance test is already frozen as plain JSON in conformance/ — 2,240 vectors plus the dimension layout, injectivity over runtime-scaled blocks, and the two deliberate aliases — so it can be checked with no Python in the loop.

Step 5's identity is not bit-exact, and this document used to say it was. The bounce ray leaves from x1 + eps·n, so the vertex it finds is not exactly on the ray from x1: the path tracer evaluates the integrand at the direction it sampled, while reuse re-derives the direction from the stored vertex, and the two differ by about eps / d. Measured at 20×20 on cornell_restir_gi, 103 of 185 samples agree bit for bit, one exceeds 1e-3, the worst is 7.3e-3, and the totals agree to 2.7e-5. What the alias in gi_cand_dim buys is that the two draw the same numbers, so they can be compared per sample rather than statistically; the residual is then explained rather than tolerated. tests/test_core.py::TestGiRestirIdentity had this right all along, and four other files said "bit-for-bit". A port that writes the equality assertion the wording invites loses a day finding out.

Step 6's acceptance is different in kind, and stronger than it looks. The graph has no floating-point arithmetic, so "agrees per sample" means nothing; what replaces it is describe() character-for-character. Because describe prints slot numbers, that one string transitively pins declaration order, the topological tie-break, culling, the lifetime intervals and the greedy colouring's first-fit rule — five things with no numeric output of their own. Sweep dirty_steps over the whole 32-element power set rather than the five domains: it is a pure function over five elements, so exhaustive costs nothing.

And build synthetic graphs. Measured across all thirteen configurations, nothing is ever culled and nothing is ever aliased, and the topological sort is the identity — two and a half of the five stages decide nothing on any shipped scene. A port can get them all wrong and reproduce every real plan exactly.

Step 7's acceptance needed a change to the oracle, and that is the finding. The energy table is measured with Engine.render(warmup) + reset_accumulation(), which clears the image, keeps the reservoirs, and rewinds spp_index to 0 — so the measured frames draw samples 0 … spp-1 however long the warm-up was, and the subtrahend renders exactly those. pt/core/render.py had no way to express that: the reference twin only took spp, so the best it could do was discard frames off the front, and the direct term — 89% of the image — then stops cancelling per sample. Measured, the no-reuse identity read 0.9989 against a control of 1.0099 instead of sitting on it. warmup= is now a parameter of render_reference, and the general lesson is worth more than the fix: a twin that cannot describe the experiment is not a twin, and the gap was invisible for as long as nobody asked the reference to reproduce a kernel-side measurement.

The digits do not transfer, and should not be expected to. §10 was measured on the f32 kernels at 128px against a 4096-spp reference; the port measures the f64 reference path at 48px, where mis reads 0.9156 of the no-reuse row against §10's 0.8960. What reproduces — and what §10 actually asserts — is the shape: exact without reuse, temporal-only weighting-insensitive (to nine decimals here, which is §6's algebraic collapse rather than a coincidence), the deficit entering through the reuse passes, and MIS recovering part of what 1/M loses spatially and only part. State the acceptance as relations, not as numbers, or a port will fail it for having a different resolution.

Each step's fixture must be mutation-tested, and that is not a formality. Step 3's fixture compares 55,184 values across four scenes and passed on the first run, and breaking the port on purpose still found two defects it could not see: EPS is unreachable through any render, and every quad in every bundled scene is a rectangle, so the dot(u, v) terms in the quad solve vanish identically. A fixture generated from the implementation only tests the branches that implementation happens to take. port/racket/test/mutations.sh is the harness; add to it as each step lands, including the mutations that are expected not to be caught.

Verification strategy#

The Python is the oracle; use it as one rather than reimplementing its tests.

  • Per-sample diff, not statistics. Render the same scene, same seed, same spp in both and compare radiance per pixel with REL_TOL = 5e-3 and MAX_DISAGREE_FRACTION = 0.02 — the tolerances the existing twin tests use.
  • Reuse the reference cache. .ref_cache/ holds converged uniform-MC references keyed by scene fingerprint. Read them; do not re-derive them.
  • Port validation/ last, or not at all at first. Shelling out to pt validate <scene> is a legitimate acceptance test for a long time.
  • Keep naive reachable. It is the wrong estimator on purpose, and the harness makes bias appear and vanish on demand. A port without it cannot demonstrate that its MIS weighting does anything.

The acceptance test for the whole port is not that renders look right. It is that the four defects in ARCHITECTURE.md reproduce their measured numbers when you reintroduce them, and vanish when you fix them.

Traps a reimplementation will hit#

Each of these is a mistake already made once here, at real cost.

TrapSymptomFinding
Shadow epsilon applied at both ends so it cancels31% of pixels disagree; f64 and f32 round differently"A shadow-ray epsilon that cancels itself"

Assuming sum() over floats is a left foldone ulp, only at 3+ live streams, under any libm tolerance"CPython's sum() over floats is not a left fold"

Two of those were found by this port and are worth their own note. Python's negative list indexing has no equivalent in most hosts: reaching scene.materials[hit.material_id] with material_id == -1 silently returns the last material, so a code path that should be unreachable produces a plausible number instead of an error. A port that raises is right to, and the fixture is what has to change — pinning the Python's answer there would freeze an accident.

And a fixture generated from an implementation tests only the branches that implementation happens to take. Both step 3 and step 4 passed on their first run and mutation testing still found real gaps in each: EPS unreachable through any render, every bundled quad a rectangle, the two acceptance gates agreeing trivially on near neighbours, and a one-ulp defect sitting under the libm tolerance. Each was closed by testing the routine directly rather than hoping a scene reached it.

What stays in Python#

  • pt/kernels/. Taichi is a real dependency and the f32 twin is what makes the per-sample diff meaningful in the first place.
  • validation/'s converged references. .ref_cache/ is expensive to rebuild and its fingerprint deliberately excludes strategy, so it cannot be gamed.
  • pt/shell/. DearPyGui, threads, viewports — nothing here is semantics.

A bridge is optional. Nothing in the port needs to call Python; comparing artifacts (.npy radiance buffers, pt edn output, pt describe output) is enough for every verification step above, and keeps the two implementations genuinely independent — which is the same reason validation/analytic.py re-implements its own vector math.
